## 3. 推荐交付顺序

1. 确认赛事条件、维护是否延期、选定发行身份和演示主路径；审阅走查 NO/缺陷/未测，不重新开展无边界排查。
2. 先同步计划书事实与成果/创新/架构说明，再做 PPT，避免同一项目出现不同状态。
3. 准备展示数据清单、长短脚本、Q&A 与恢复/模式切换操作单；只使用真实记录/真实截图，保留原时间与模式。
4. 在代码冻结后进行两轮计时演练：第一轮正常路径，第二轮演练已批准的只读故障/切换与操作中断处理。主动停止 DB、模型或其他服务不由材料授权自动包含；需要此类演练时另行明确范围。
5. 建议 T-7 前选定版本/材料结构，T-3 前完成两轮排练并停止修改演示路径，T-1 前提交副本校验与负责人签署。窗口不足时减材料长度/改用预录，不能跳过真实性/身份检查而冒险改核心。

LIVE 主线可以读取已完成且来源清楚的真实运行记录；口播必须说明“读取当前数据库中的某时刻运行”，不能说正在现场执行完整新 A。若要现场发起新 LIVE A，应在另获场景运行授权后实测其端到端时长，再决定是否能放进演示，不把安装后只读浏览 60.2 秒的旧测量套到新运行或冷安装。

历史记录超出查询窗口时使用真实登记回放，或者说明切换时间窗；不能改时间戳让旧数据显得新鲜。TTL已过的遏制结论要说明其历史有效性、root cause unresolved/VERIFYING等实际状态，不声称已根治或自动关闭。

## 6. 现场预检、恢复与模式切换

参考[操作卡](ZHIYU_COMPETITION_OPERATION_CARD_v1.0.0.md)、[快速上手](ZHIYU_QUICK_START_v1.0.0.md)、[部署](DEPLOYMENT_GUIDE.md)、[备份恢复](BACKUP_RESTORE_GUIDE.md)。这些旧文档的 DF-001–003 需按维护/材料授权同步；本轮没有替它们写回。

| 条件 | 处理原则 | 可以切到什么 |
|---|---|---|
| 已安装，owned PG/ingress运行、API ready | 正式start/status、health/ready核对、重新登录/快照；需要新Demo才启独立可信Worker | LIVE读取；新动作另受固定场景授权 |
| PG/ingress停止、出现reference_database_not_running | 按已演练流程核对metadata/project/labels/Compose服务/卷/网络，先恢复既有owned infra再官方start；端口从真实映射刷新 | API恢复后LIVE或登记REPLAY；未恢复时不能声称网页回放可用 |
| 缺服务/foreign ownership/映射非回环 | 停止恢复，不猜容器ID、不重装、不启动别人的服务；由负责人决定换已验证环境或材料 | 明确标时点的外部预录视频/截图 |
| API进程停止，infra正常 | 只做官方start/status/health/ready；会话与内存快照丢失后重新登录/获取 | 恢复后读登记REPLAY，或正常LIVE读取 |
| 模型不可用，但API/DB正常 | 不让模型故障影响确定性安全骨架；演示E已有记录并说明实际来源 | 登记E回放/已完成结果；不是偷偷换假模型 |
| Worker不在运行 | 已完成事件/回放可读；不发新LIVE意图后等待“自动成功” | 读已登记结果/回放；现场恢复Worker需可信operator与明确授权 |
| Sensor缺失/过期 | 保持UNKNOWN/INCONCLUSIVE；不补假心跳，不改为PASS | 当前故障读视图，或明示切换历史登记档案 |
| 429/读失败/空列表 | 放慢读操作，等待/重试，检查环境/Scope/时间窗；不降低读限额/放宽授权 | 已知登记记录；故障仍存在则外部预录 |
| 档案hash不符/未登记/撤权 | 拒绝该档案，不手改hash/ACL；选择另一个合法档案 | 经检查的备用登记档案或外部预录 |

操作员不运行任意容器ID救场，不重启全Docker/WSL影响其他项目，不`down -v`，不修改生产/正式证据。若演示涉及已批准的新Lab运行，先看到实际CLEAN与资源归属核对后再停止Worker/API；取消后续步骤不等于已撤销动作。保留历史录制与失败记录。

模式切换口播建议：“下面切换到该版本在受控实验环境中的历史登记回放，保留原时点与结果，不会再执行模型或动作。”外部视频则说“这是某次实测的预录画面，当前故障尚未恢复”。页面模式、口播和材料标签一致。

## 7. 展示数据与材料真实性

展示数据清单应记录 run_id/incident_id、environment/Scope、场景版本、来源时间、model_source、模式、预期/实际结果、Verification时效、cleanup_status、档案/报告hash及证据入口。只列公开字段；不带私密deployment文件、密钥、数据库URL或raw locator。

优先使用已验证登记记录和正式截图；需要新演示数据须经明确授权放入新副本/新目录，不覆盖原Evidence Index或历史包。F22数据仅用于隔离补验，不挪作“正式场景有大量真实攻击”的展示证据。合成负载、脚本反例、真实模型、真实Sensor与回放分别标识。

PPT/简介建议结构：现实问题 → 目标用户 → 一条闭环 → 核心自研模块与第三方边界 → 两张架构视图 → 真实产品路径 → A与反例 → 分口径工程成绩 → Stable Prototype限制 → 有界下一步。无证据的市场数字、客户、合作、专利/软著、营收与AI提升百分比不补写。

## 9. 交付验收、冻结与停止

材料完成后应核对：计划书/PPT/简介/架构/脚本版本一致；所有数字可回溯；UI/Logo正确；LIVE/Replay/预录标签一致；三处旧文档状态不误导；长短演示两轮时长合格；鼠标替代/启动恢复分支可执行；备选档案/视频能打开；正式ZIP身份不变；提交副本无secret；赛事格式/字数/容量/负责人签署完成。

比赛临近时建议保持 v1.0.0，先用材料附注披露启动契约、键盘限制和F22未测；若无法安全准备LIVE，则明示使用登记回放或外部预录。不能为了避免承认限制而临场改代码、改状态、改Evidence或新开权限。
