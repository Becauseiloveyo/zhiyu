## 5. Timeline 数据计划

统一输出：`entry_id=(environment, source_kind, source_id, phase/version)`、`incident_id`、`occurred_at`、`recorded_at`、`time_basis`、`clock_status`、`status`、`source_refs`、`evidence_refs`、`explicit_links`、`data_origin`、`run_mode`、`model_source`、`history_completeness`。不可从时间相邻推导因果。未来分页按所选时间基准、固定 kind 优先序、稳定 ID 排序；数据库 UTC 原值保留。

| Timeline event | 来源对象 / 时间字段 | 状态与关系 / Evidence reference | 注意事项 |
|---|---|---|---|
| Event observed | NormalizedEvent.source_timestamp | outcome/clock_status；event ID、raw_ref、source/target、origin_event_id | source clock 可能 SKEWED/UNKNOWN；不是控制面接收时间 |
| Raw received / normalized | RawRecord.received_at；RawDelivery.created_at；Event.ingested_at；EventReceipt.received_at | delivery disposition、normalization_ms、event_id、raw_id/hash、trace_id | normalized 完成时刻无独立字段，使用 created_at/ingested_at 并标 record-time proxy；错误 raw 无 event_id |
| Group / correlation | GroupMember.added_at、CorrelationDecision.created_at、GroupState.created_at/updated_at | INPUT/EXCLUDED、output_group_id、rule/version、event refs | EventGroup.first/last_seen_at 是样本窗口，不是分组操作时间；更新历史非全量 |
| Incident promotion | PromotionRecord.created_at、Incident.created_at | CREATED/MERGED/UPDATED/NOT_PROMOTED，group_id/version、IncidentEvent.evidence_id | NOT_PROMOTED 的 incident_id 为 null，不能塞进某 Incident；关联排除项保持 |
| Context creation | DecisionContext.created_at/valid_until、ContextBundle.created_at | context_id→snapshot_id/incident/version/scope；manifest evidence/exclusions/conflicts | 不将裁剪过的模型上下文当完整 Incident 时间线 |

| Situation analysis | SituationAnalysis.created_at | context/request/model_run/state_entity、status、grounding；output finding refs | REFERENCE_GROUNDED ≠ 自然语言结论正确 |
| Proposal / Decision | AIProposal.created_at、AIDecision.created_at | parent_verification_id、analysis/context/plan ID；REJECTED/SHADOW/fallback 等 | 被拒绝的 proposal 无 plan 是合法终态，不制造 Action |

| Action intent / attempt | Action.created_at/expires_at；Attempt.started_at/finished_at；Task.claimed_at/started_at | ActionControl status、generation、worker、Attempt error/reconciliation_state | Task 可变状态不是全量事件日志；不伪造每次重试/renew 历史 |
| Action result / reconcile | ActionResult.started_at/completed_at；相关 Audit.timestamp | dispatch→attempt→action；output hash、execution_outcome、Lab before/intended/after、evidence refs | UNKNOWN Attempt 历史与最终 reconciliation result 并列；当前 target 状态不能代替历史回执 |
| Verification checks / verdict | Runtime.created_at；Observation.started_at/checked_at；Result.started_at/finished_at/valid_until；Effectiveness.decided_at | objective/claim、三维状态、action_result_id、evidence、qualification failures | 执行成功不等于 assertion PASS；expired PASS 标过期而非重写旧状态 |

## 6. 已知缺口与不新增事实原则

1. 没有完整历史 Resource locator、全部 Sensor 变化、每次 Task 状态快照；Audit reason 是辅助证据，不是可反向还原任意旧 JSON 的保证。
2. `ServicePrincipal` 只有 environment_ids/permissions，没有 viewer scope grants；产品层必须增加显式只读 Scope 可见性策略，不能将请求中的 scope_id 当授权。
3. `GET /health` 返回静态默认值及旧 milestone 字符串，不是某环境 AI/动作启用状态；产品健康从受保护配置与数据库读，规划扩展而非篡改已封存证据。
4. 现 API 多处返回全列或合同大对象；产品 DTO 需字段白名单、文本长度和 redaction，不能用 `record(row)` 直接绑定前端。
5. 本轮没有发现必须重写核心引擎的阻断。未来产品接入需扩展查询层、验证读权限、处理有界一致性和持久演示状态。冻结基线的已测语义不变。
