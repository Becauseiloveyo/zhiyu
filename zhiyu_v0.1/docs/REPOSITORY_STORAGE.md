# 仓库与本地文件边界

GitHub 仓库保存当前源码、测试、依赖锁文件、配置样例、数据库迁移、架构契约、产品文档、品牌资源和参考安装所需的前端生产构建。

测试所需的固定样本和架构基线分别随 `tests/fixtures` 和 `baseline` 提交，测试运行生成的查询计划等材料仍属于本地证据。`.gitattributes` 保留原文件字节，避免跨平台换行转换破坏冻结契约和构建校验。

以下文件只保留在操作员本地，并由 `.gitignore` 排除：

- `.work/`：私密部署配置、运行身份、模型、备份以及历史实验材料。
- `artifacts/` 与工程内 `artifacts/`：历史封版包、原始审计/验收证据、扫描结果。
- `docs/*-runtime/`：原始实验室采集记录。历史报告对这些路径的引用表示本地证据路径。
- `output/`、`tmp/`、`.ui-preview/`、`.playwright-cli/`：生成过程、旧预览和工具临时文件。
- `node_modules`、虚拟环境、构建/扫描缓存，以及任何真实密钥、会话、数据库文件和模型权重。

不要用 `git add -f .work` 或全目录打包的方式同步运行环境。恢复安装时按照备份恢复指南处理私密备份，不能以源码仓库代替数据库备份。

本地精简优先删除可由锁文件恢复的旧安装依赖、旧 UI 试验依赖和可重新下载的扫描缓存。正式部署、仍使用的开发环境、模型、独有证据和恢复备份保留；不要直接删除 Docker volume，也不要以通用 `docker system prune --volumes` 清理此项目。

日常更新在当前工作副本中进行：先检查 `git status`，完成必要验证，再提交和推送。前端发布还需重建 `frontend/dist` 并更新实际部署；单纯推送 GitHub 不会自动重启本机服务。
