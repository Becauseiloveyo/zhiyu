# v0.9 Attack / State Graph Data Model Plan

> 本文保留 2026-09-28 Inspect + Plan 历史快照。当前 v0.9.0 已完成并 PASS / CONTROLLED LAB；实现与测试结果以 [最终报告](VALIDATION_REPORT_v0.9.0.md) 为准。下文 PLANNED/BLOCKED/未实现描述仅对应编写当时。

状态：**v0.9.0 PLANNED**。这是 visualization projection plan，不修改 ai.5 Contract，不实现图前端，也不选择图组件库、布局或样式。

## 1. 已有事实与实现证据

- [ResourceRef / Observable / StateEntity / StateRelation](../src/zhiyu/domain/contracts.py) 定义资源、可观测值、带有效期的状态和关系。
- [ORM](../src/zhiyu/db/models.py) 持久化 `resources/state_entities/state_relations`；[基础关系表](../src/zhiyu/db/infrastructure.py) 含 `event_resources/scope_resources`；[Incident lineage](../src/zhiyu/db/incident_intelligence.py) 含 `incident_events/incident_groups`。
- [AI analysis](../src/zhiyu/ai/analysis.py) 实际写入 `AI_SITUATION_ANALYSIS`，明确 `claim_kind=INFERENCE`、`MODEL_SELF_REPORTED_UNCALIBRATED`，证据链接仅指上下文输入，不证明模型结论。
- [Verification state update](../src/zhiyu/verification/replan.py) 实际写入 `VERIFICATION_OBSERVATION` 和 `VERIFICATION_INFERENCE`，并用 `verification_state_updates.entity_ids` 绑定结果。
- [ContextManager._state](../src/zhiyu/ai/context.py) 已区分 CONFIGURATION、OPERATIONAL_TELEMETRY、观察、推论/模型假设；注册 Resource 的 availability/criticality 未测就保留 UNKNOWN。
- 本轮检索全部产品源码，只发现 `StateRelation` 的契约、映射与表定义，**没有发现产品运行链的关系写入者**。因此第一版不得假设 `state_relations` 有完整拓扑或攻击边。测试、bootstrap 配置或以后显式入库的记录也要分别标来源。

结论：可实现的是**证据支持的资源/事件/状态关系投影**。名称可沿用项目要求的 Attack / State Graph，但输出必须声明 `causal_attack_path=NOT_ESTABLISHED`，除非某条真实关系有明确、可核验的因果证据。没有证据的关系保持 UNKNOWN，不为连通图填边。

## 2. 节点类型与稳定身份

所有节点 ID 必须带 environment 和 kind 命名空间；同名字符串跨类型不合并。节点数为零是合法结果。

| 投影节点 | 合法来源与 ID | 可输出字段 | 不能据此宣称 |
|---|---|---|---|
| Resource | `resources.resource_id`；`resource:{env}:{id}` | resource_type、binding_version、白名单 display_name/locator 摘要 | 注册即在线、无漏洞、已受保护 |
| Host / Identity / NetworkEndpoint | Resource 的 subtype，分别依据 resource_type；使用同一个 Resource ID，不另造重复资产 | 已验证结构的 locator 子字段；Identity 只输出获准账号摘要 | USER observable 自动变成真实 Identity；IP 自动变成稳定 Host |
| Address / Observable | NormalizedEvent.observables 中真实条目；或者 Resource 当前 locator；ID 包含 env、规范化类型/值/角色的摘要 | value（脱敏）、observable_type、role、出处、时间 | 地址所有权、历史 DHCP 绑定、同 IP 同资产；URL 内容安全 |
| Sensor | `sensor_health.sensor_id`，独立命名空间 | status、heartbeat、last_event、coverage_scope_ids、config_version、freshness | collector_id 字符串与 sensor_id 相同即同一实体；健康即攻击已阻断 |
| Event | `normalized_events.event_id` | source/ingest time、clock_status、source_type、data_origin、provenance_group | 来源报告的 SUCCESS 即攻击成功或防御成功 |
| EventGroup / Correlation | `event_groups.group_id` / `correlation_decisions.decision_id` | 窗口、版本、规则、INPUT/EXCLUDED | 聚合因果、攻击链步骤顺序 |
| Incident | `incidents.incident_id` | status、priority、state_version、时间、有限关联摘要 | 关联资产必然被攻陷；CONTAINED 等于根因修复 |
| Evidence | `evidence.evidence_id` | hash、claim_kind、trust、provenance、observed/collected/valid_until、data_origin | hash 正确即内容真实；共享 provenance 的多条证据等于独立来源 |
| StateEntity | `state_entities.entity_id` | entity_type、claim_kind、state_version、白名单 attributes、validity | 当前最新一行代表所有历史时刻，或推论变成观察 |
| Verification | `verification_results.verification_id`；pending spec 单独标 runtime 类型 | objective、claim、三维、总状态、有效期 | 过期 PASS 仍有效；EXECUTION_SUCCESS 代表安全 PASS |
| Analysis / Proposal / Plan / Action | 各自明确 ID，可作为按需 lineage 扩展 | 类型、状态、时间、拒绝原因、关联 ID | Task 依赖或 Plan 建议变成攻击路径；Proposal 变成实际执行 |

ResourceRef 虽允许 KUBERNETES/CLOUD/SAAS 等枚举，并不意味着这些环境已采集或验收；只显示确有获准记录，并继续注明相应 NOT VALIDATED 范围。

## 3. 边必须来自明确事实

| 边类型（拟议 projection vocabulary） | 来源 | 方向与语义 | 校验条件 |
|---|---|---|---|
| EVENT_SOURCE / EVENT_TARGET | `event_resources.role`，并与 Event source/target IDs 对照 | Event → Resource，表示记录关联角色 | 同 env、实际关系行、端点可见；记录缺失/冲突而非猜测 |
| EVENT_ACTOR | Event.actor_resource_id（非空） | Event → Resource，来源认定的 actor | ID 可解析且读权限允许；不是确认攻击者身份 |
| HAS_OBSERVABLE | Event.observables | Event → Address/Observable | 保留 type/role、source event 和时间；不得跨事件推导通信或身份 |
| CURRENT_LOCATOR | Resource.locator + binding_version | Resource → Address | `basis=CONFIGURATION`，仅当前注册绑定；非历史观测 |
| MEMBER_OF / INPUT_TO / EXCLUDED_FROM | GroupMember、DecisionInput.role、CorrelationDecision | Event → Group/Decision | 保留 EXCLUDED 和 reason，不能为了简洁删除矛盾/异常 |
| PROMOTED_TO / ASSOCIATED_WITH | IncidentGroup + PromotionRecord | Group → Incident | group_version、promotion outcome/time；只关联确有 incident_id 的记录 |
| INCIDENT_EVENT / AFFECTS_RESOURCE | IncidentEvent / Incident.affected_asset_ids | Incident → Event/Resource | `ASSOCIATION`，不是 causal attack；多 Scope 情况服从读策略 |
| EVIDENCE_FROM | Evidence.source_event_ids / IncidentEvent.evidence_id | Evidence → Event | 双向一致性校验，空 source_event_ids 的验证证据仍合法，另按 observation 绑定 |
| SUPPORTS / CONTRADICTS | Evidence.supports / contradicts | Evidence → 明确且可解析的 statement/object | 当前字符串非统一 typed FK；只有可识别的允许格式才转成边，否则保留原引用摘要并标 UNRESOLVED，不按任意字符串猜节点 |
| STATE_EVIDENCE | StateEntity.evidence_ids | StateEntity → Evidence | 所有引用同 env、授权可见；模型上下文输入不变成模型结论被证实 |
| STATE_RELATION | StateRelation.source_entity_id/destination_entity_id | StateEntity → StateEntity，保留 relation_type | 端点、证据、state_version、valid_from/until 必须完整；relation_type 自由文本要限长和白名单语义映射，未知类型原样标未解释 |
| VERIFICATION_EVIDENCE / PRODUCED_STATE | VerificationResult.evidence_ids、VerificationStateUpdate.entity_ids | Verification → Evidence/StateEntity | 有独立结果来源；inference 和 observation 不合并 |
| ANALYSIS_CONTEXT / PROPOSED_PLAN / EXECUTED_TASK | Context/Analysis/Proposal/Plan/Task/Action 的显式 ID | 业务 lineage，按真实外键连接 | 被拒绝/Shadow 的 proposal 可能没有执行计划，允许断开的分支 |
| SENSOR_COVERAGE | SensorHealth.coverage_scope_ids | Sensor → Scope reference | 这是配置/健康登记，需 coverage_validated 和时效；没有可信 collector→sensor 映射时不造 Sensor→Event 边 |

图投影禁止依赖任意文本实体识别自动新增边；不从一个源 IP 与目标 IP 共现就创建 `COMPROMISED/LATERAL_MOVEMENT/EXPLOITED`。即便一条源日志写了 attack，也必须将它表达为 SOURCE_ASSERTION。

## 4. Projection contract（待实现）

`ResourceStateGraphProjection` envelope：

- `projection_version`、`environment_id`、`scope_filter`、`access_policy_version`、`root_ref`、`snapshot_id`、`as_of`、`window`。
- `run_mode`、`source_run_id`、`source_rc/source_digest`、`data_origins`、`model_sources`；多个来源不挤进一个真假二值字段。
- `nodes[]`：稳定 ID、类型、source_ref/version、白名单 attributes、claim_kind/basis、observed_at/valid_from/valid_until、freshness、trust_status、provenance refs。
- `edges[]`：稳定 ID、source/target、typed relation、relation_basis、原始 source refs、evidence refs、时间范围、解析/授权/有效性状态。
- `coverage`：queried kinds、missing/unresolved/expired/conflicted 总数、history_completeness；敏感排除项只返回不泄露对象身份的摘要。
- `truncated`、`limits`、`returned_counts`、可知时的 `omitted_counts`、`frontier_cursor`；无法廉价精确计数则 `omitted_count=null`，不做昂贵 COUNT 或编造 0。

稳定边 ID 从已知 source row/关系类型/端点/版本生成，不按图中坐标或本次结果下标生成。相同证据多个角色可以有不同语义边，但不计作多份独立来源。

## 5. 时间、质量和 UNKNOWN

1. CURRENT 与 HISTORICAL 是查询语义，不是视觉选择。CURRENT 只对指定 as_of 仍有效的观察作当前声明；HISTORICAL 保留原 valid_until、原 verdict 和证据时间，明确现在可能失效。
2. Resource 当前 binding 无完整历史表。历史 Event 的 resource IDs 是当时固化引用；当前 locator 只作为当前配置附注。不能由当前 `10.x` 反补旧事件绑定。
3. StateRelation 无全版本历史的保证；同一 relation_id 当前内容不能表示过去所有版本。返回 `history_completeness=PARTIAL`。
4. UNKNOWN、UNRESOLVED、STALE、CONFLICTED、EXCLUDED 均有明确字段。无法解析的边不连到占位“攻击者”；可保留 unresolved reference 摘要。
5. 缺 Evidence 或来源不可信不等于发现消失。保留原 claim 类型与验证质量；不能因图上有边就上调结论。模型 confidence 原样注明未校准，禁止聚合成攻击概率。

## 6. 实现、性能和迁移决策

拟新增模块 `product/graph.py`、`product/contracts.py`、只读 graph query；复用 ORM 和受权查询，**不引入图数据库、图推理引擎或新核心关系持久化**。

第一版查询根必须是授权 Incident 或 Resource；SQL 获取有限 ID 集，再按集合批量取相关行，禁止逐节点递归 N+1。初始上限 200 nodes / 400 edges / depth 2，引用摘要每元素最多20项，窗口和响应体上限见 [API Gap](V0.9_API_GAP_ANALYSIS.md)。展开请求不允许绕开累积快照上限；超限明确截断。

在短只读一致事务内创建有界投影 snapshot；graph、timeline、report 如声称同一快照，必须引用同一个不可变衍生 snapshot。禁止跨多次 LIVE 查询拼接后声称同一时刻。Index 增量仅在实际 PG query plan 证明必要时提出，不预设 migration。

## 7. 未来测试与验收

规划测试：真实 FK/JSON 引用闭包；同名跨 env/kind；同 IP 多 Resource/绑定更换；actor 缺失；INPUT/EXCLUDED；supports 与 contradicts 并存；缺失/跨域 Evidence；expired StateEntity；空 StateRelation；未知 relation_type；AI inference 不升级为 observation；pagination/truncation；同快照展开一致；非法 root/scope、撤权、恶意文本、超量邻接；原始 hash 保留但展示脱敏。

接受条件：每条边都能追到实际字段/关系行；没有模型补边；没有无证据攻击路径；CURRENT 不包含未经标识的过期安全结论；有界 SQL 和响应；原 381 regression 保持。图的视觉、位置、颜色、动效和点击/展开交互全部 **BLOCKED — WAITING FOR USER UI DESIGN**。
